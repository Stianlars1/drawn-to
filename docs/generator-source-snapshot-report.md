# Generator source snapshot hardening

Implemented in the generator worktree; no commit, aggregate rebuild, publication or new showcase capture performed.

## Changes

- `scripts/lib/generator-catalog.mjs`: added content-addressed immutable frame writing, partial-manifest merging, full SHA-256 frame validation, and deterministic authoritative-resource digesting. `makeCatalog` now requires a `frames` manifest option and embeds `thumbnailSha256` alongside the hashed thumbnail path. Catalog ID construction remains SHA-256 of `JSON.stringify(content)`, truncated to 20 hex characters.
- `scripts/build-generator.mjs`: validates manifest identities, content-addressed addresses and actual JPEG bytes before building. Knowledge digest covers all portable `skills/drawn-to` resources (including guides and media), explicitly declared scene implementation files, and current frame evidence. JSON objects are canonicalized; filesystem timestamps, unrelated generator UI, historical frame files, `generator-release.json`, and generated `showcase-styles.json` do not affect this digest. The existing immutable published-source stamp rule remains enforced.
- `scripts/capture-generator-sources.mjs`: screenshot bytes are written to exclusive-create hashed paths; existing snapshots can never be replaced. Every run, including `--only`, merges the successful capture set into the previous manifest and atomically replaces that manifest. Optional `--source-revision=<full commit>` records operator-supplied provenance without pretending to verify the served revision automatically.
- `site/js/generator/core/catalog.js`: validates each thumbnail's content-addressed URL against its full hash after existing catalog-fingerprint verification. Actual image bytes are checked by the offline builder; the browser does not eagerly download all 70 images.
- `site/assets/generator/scenes/frames.json` and 70 new hashed JPEG files: original bytes preserved exactly. Provenance identifies existing captures from baseline `f3cc3ed2b69a8e4ced31c8c4217e7a044dc8f505`, captured before generator showcase/header edits. Existing legacy JPEG files were retained for old development URLs, and historical hashed snapshots are never deleted.
- `tests/generator/catalog.test.mjs`: eight Node built-in tests cover duplicate/missing properties, exact source headings, missing/duplicate/tampered frames, deterministic catalog IDs, immutable older thumbnails, partial capture merging, corrupt-history refusal, authoritative digest sensitivity and exclusions, and browser fingerprint/thumbnail validation.
