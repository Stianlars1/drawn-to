## Type & color
- Two-family system, strictly partitioned. Mono (Fraktion/Berkeley-Mono character): nav, pills, FIG labels, CLI commands, param keys, axis labels, CTAs - always uppercase or code-case, ~11–13px, tracking ~0.05–0.1em. Grotesk sans (Diatype/Neue-Montreal character): card titles, descriptions, spec lists, UI-fragment text - ~22px/31px for title+body (title and body the SAME size; hierarchy via color, not scale).
- Palette: page #0a0a0a–#0e0e0e; hairlines #202020; primary text #ffffff; body #929292; secondary #8f8f8f; dim labels/indexes #454545–#555; nav pill fill #4b4b4b with #ececec text.
- Accents are semantic only: green #a9e494 for good scores and terminal "$"; red #c25b52 for failing score; amber #dcc17e for mid score; hero streams teal-green/indigo. No decorative color anywhere else - a strict grayscale ladder plus data-driven hue.
- Contrast strategy: 4-step gray ramp (white > #929292 > #555 > #202020) does all hierarchy work; anything colored is information.

## Graphic language
- Engineering-plate aesthetic: every card is a numbered figure (FIG.1–FIG.4) echoing patent drawings/textbook plates; triple numbering system (nav 01–04, sections 01/02, specs 1.1–2.3) cross-references the whole page like a spec document.
- Features are depicted by their literal mechanics, not metaphors: the CLI loop is a state machine annotated with the real commands; hosted evals are the actual registry cards and score table; training is a real-looking reward curve with plausible hyperparameters; distributed inference is routed paths on a globe. The illustrations double as documentation.
- Construction: 1px hairline strokes on black, small geometric nodes (circles/squares ~8–10px), dashed guides and crosshairs, dotted leader lines, depth via opacity dimming (stacked cards at ~25–40%) rather than shadow or blur.
- Texture: hero-only halftone/CRT dot matrix in perspective - each "dot" is a micro cluster of RGB sub-pixels, reading as machine data; colored streams imply live throughput.
- Fill is reserved for interaction: the only solid shapes on the page are white buttons (Evaluate, CTAs, START TRAINING).

## Why saved
Owner note: "rectangular, sleek, editorial 4 feature cards with heavy focus on vectors/illustrations/graphics to show Prime Intellect's functions visually. Liked: graphic details and pictorial depiction of core features instead of text."

Verified. The craft that earns it: (1) each illustration is product-truthful - real commands, real hyperparameters, real registry names, so the picture carries the information a paragraph normally would; text shrinks to 3 lines + 3 bullets per card. (2) The FIG.n plate system plus triple numbering turns a marketing page into a technical document, matching the audience. (3) The grid is a genuine shared-border table (single 1px divider between cards, radius 0, no shadows) - a discipline generic AI pages break by floating rounded cards with gaps. (4) Title and body share one font size; hierarchy is done purely with a 4-step gray ramp. (5) Color is never decoration: green/red/amber appear only where a score or terminal prompt makes them meaningful. (6) Micro-details a generic page misses: careers count badge "24" in the nav, ghost circles behind diagram nodes, dotted leader lines, rear-card opacity stacks, sub-pixel RGB dot texture in the hero.

## Extractable rules
- Set page background #0a0a0a and draw ALL structure with 1px #202020 rules; no shadows, no card fills.
- Use radius 0 on every container, button, and pill; rectangles only.
- Build feature cards as shared-border grid cells (one 1px divider between neighbors), ~700px wide, ~65% illustration / ~35% text.
- Label each card's visual as a numbered plate ("FIG.1") in 11px mono #454545, 16-20px from the top-left corner.
- Number everything three ways: nav items 01-04, section titles 01/02, spec bullets 1.1-2.3.
- Split type by role: mono uppercase 11-13px (+0.05-0.1em tracking) for labels/commands/CTAs; grotesk sans ~22px/31px for titles and body.
- Keep title and body the same size; create hierarchy with a gray ramp (#fff > #929292 > #555) instead of scale.
- Depict features with 1px line-art of the product's literal mechanism (real commands, real params, real UI fragments), never abstract metaphors.
- Reserve hue for semantics: green #a9e494 = success/prompt, red #c25b52 = fail, amber #dcc17e = mid; everything else grayscale.
- Show depth by dimming stacked elements to 25-40% opacity, not by shadow or blur.
- Make solid white the interaction color: only buttons get filled rectangles (white bg, black 11px mono uppercase, ">" suffix, ~28px tall).
- Use dotted leader lines between mono keys and white values in spec/param tables.
