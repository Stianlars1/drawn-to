# Interactive design-system guidelines as live inspector

## What we see
A 28.2s screen recording (986×720, 60fps source) of an interactive design-system guidelines prototype: an iPhone 15 Pro mockup on a neutral canvas whose screens are themselves the documentation. Hovering any element - spacing gaps, page title, body copy, section headers, a 3D illustration - reveals a Figma-inspector-style tooltip with a plain-language rule plus a monospace token table (type / style / color / gap-below / size). A floating state switcher cycles the same page through Default → Long title → Two-tone title variants, and a black arrow FAB pages between a spacing wireframe, a real FHSA content page ("Save for your first home", Wealthsimple 'W' monogram on the 3D keychain), and an illustrated hero.

## Layout & composition
- Canvas: flat #E5E5E5 backdrop; phone mockup centered-left, ~340px wide at rest, camera dollies to ~1.25× toward hovered regions.
- Screen bg #F2F2F2; skeleton sections fill #F5F5F5 with centered #9CA3AF labels.
- Documented spacing (shown as live measurement overlays): 16px page gutter both edges at every breakpoint; 16px top-nav → first-section gap; 40px between sections; 8px title → body gap (shown as an underline ruler with an "8" chip).
- Measurement bands span full content width; value chips centered in each band: idle = white pill, 1px blue border, blue monospace numeral; active = solid blue (#3B82F6-ish, sampled #478CCD) with white numeral.
- Highlight fill on hovered band ≈ #BCD3F3 (blue at ~25% over the gray), 1px #3B82F6 border; all bands sharing the hovered token light up simultaneously.
- Tooltip card: white #FDFDFD, radius ~14–16px, padding ~16px, shadow ≈ 0 12px 32px rgba(0,0,0,0.12), anchored to cursor with slight offset; content width ~300–360px.
- Nav: floating white circular back button (~36px) top-left; black pill FAB (~64×40, radius ~16px) bottom-center with white → icon; pressed state dims to gray #9CA3AF.
- State switcher floats outside the phone, right side: 36px blue (#2F80ED) circular chevron button, label below ("Default" / "Long title" / "Two-tone"), 3 pagination dots with active dot in blue.

## Card anatomy
Tooltip anatomy (the core reusable component): row 1 title at ~15px/600 with a small ◇ diamond glyph prefix for component-level entries ("◇ Header"); rows 2–6 body at ~13–14px regular #374151, ~1.45 line-height; then a key–value spec table - keys lowercase monospace ~12px in #9CA3AF (type, style, color, gap-below, size, render), values as monospace chips on #F0F0F0 pills, radius ~4px, e.g. `Page Title`, `text-xlarge-medium`, `strong-fg`, `8px`, `375 × 260`, `native size`. Text ratio ≈ 70% prose / 30% token table.

## Type & color
- Demo app face: geometric grotesque (Wealthsimple-style). Page title 32px / weight 500, sentence case, #1A1A1A ("strong-fg"). Section headers medium size / 500 ("text-medium-medium"). Body 16px/22px in soft gray #6B7280 ("soft-fg" / text-secondary). Two-tone anchor value "$135,346" drops to tertiary gray #9CA3AF ("subdued-fg-title") while the framing sentence stays primary.
- System palette: canvas #E5E5E5, screen #F2F2F2, skeleton #F5F5F5, tooltip #FDFDFD, ink #1A1A1A, secondary #6B7280, tertiary #9CA3AF, accent blue #3B82F6 (chips/borders) and #2F80ED (buttons), highlight wash #BCD3F3, chip pill #F0F0F0, FAB black #111.
- Contrast strategy: one hue only (blue) reserved exclusively for annotation/measurement; the documented UI itself stays grayscale + content, so overlays never compete with the subject.

## Graphic language
- Documentation rendered as inspector overlays on real UI, not static spec pages: blue measurement bands with monospace value chips (Figma redline vocabulary), dashed blue selection frame around the illustration bounds, underline rulers for gap-below values.
- The token table teaches the system's actual token names (text-xlarge-medium, strong-fg, soft-fg, subdued-fg-title) - the docs speak in code.
- Guideline copy is opinionated and behavioral, not descriptive: "Guideline, not a hard rule - tighten to group closely related sections", "Cropping reads as broken; dropping reads as intentional", "balance so titles don't leave an orphan".
- 3D illustration: photoreal render of brass keys + sage-green leather fob with gold 'W' monogram (#C9A24B gold, #A8AD98 sage), floated on the flat bg at native 375×260 - premium fintech warmth against a neutral system UI.

## Why saved
No owner note. Tweet text: "interactive design system guidelines". This is the owner's taste profile in one artifact: guidelines that SHOW instead of describe. The craft decisions a generic attempt would miss: (1) the documentation surface IS a working UI - every rule is verified against a live example the moment you hover it; (2) shared-token highlighting - hovering one 40px gap lights every 40px gap, physically demonstrating "this is a token, not a coincidence"; (3) tooltips carry real token names in monospace chips (text-xlarge-medium, strong-fg), collapsing the designer-developer translation layer; (4) the rules encode judgment, not just values - fallback behavior ("drop to text-large-medium - don't shrink further"), edge cases (long-title state), and taste calls ("cropping reads as broken; dropping reads as intentional"); (5) the state switcher proves the rules hold across Default/Long/Two-tone variants instead of documenting one happy path; (6) a single annotation hue (blue) kept strictly separate from the documented UI's palette. It's the Figma-inspector mental model turned into product documentation - design-engineer-grade guidelines.

## Extractable rules
- Document spacing on a live skeleton: blue measurement bands with centered monospace value chips, idle = white/blue-outline, active = solid blue/white.
- Highlight every instance of a token on hover, not just the hovered one - teach "token, not coincidence."
- Reserve one annotation hue (blue #3B82F6) exclusively for meta-UI; keep the documented UI grayscale + content.
- Tooltip spec card: white, radius 14–16px, 16px padding, shadow 0 12px 32px rgba(0,0,0,0.12), title 15/600 + ◇ prefix, body 13–14 regular, token table below.
- Token table rows: lowercase monospace gray key + monospace value chip on #F0F0F0 pill, radius 4px; use real token names (strong-fg, text-xlarge-medium).
- Write guideline copy as behavior + fallback: state the default, the breaking condition, and the exact downgrade path (32px → text-large-medium, never regular).
- Add a state switcher (Default / Long title / Two-tone) and let users verify rules survive every variant.
- Use 16px page gutter at every breakpoint; put breathing room inside the content area, not the gutter.
- 40px between sections as a guideline: tighten to group, loosen to break.
- 8px title-to-body gap everywhere; show it as an underline ruler with a chip.
- Motion budget: tooltip fade+slide 150–200ms ease-out, highlight 120ms, camera zoom 600ms ease-in-out, page crossfade 250ms - no springs in documentation UI.
- Render illustrations at native size (e.g. 375×260); if copy would compress the image below ~1/3 of the surface, drop it entirely - never scale down.
