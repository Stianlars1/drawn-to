# Procedural UI sound kit landing playground

## What we see
A 61s walkthrough of "sonaut" — an airy, white landing page for a procedurally generated UI sound kit. The hero is a live playground card: eight category pills (Tap, Hover, Transition, Success, Error, Warning, Notification, Experimental) each swap in a bespoke micro-scene that acts out the UI moment the sound belongs to — a tap burst, a hovering button that lifts, an image toggle, a confetti toast, squishy error/warning characters, an iMessage thread, a gradient waveform. Every play prepends a real row (name, Hz, duration) to a "Recent sounds" list below; a 3-step "Use it in your project" section with a one-line code snippet closes the page.

## Layout & composition
- Single centered column, max-width ≈ 720px on a ~1440px viewport; pure #ffffff page, no nav chrome beyond a tiny centered "sonaut" wordmark (13px) at top.
- Hero stack, center-aligned: H1 (2 lines) → 2-line subhead → 1-line bold tagline → playground card, vertical rhythm ≈ 28 / 16 / 28px.
- Playground card: ~575×500px, radius ~14px, 1px border #ececec, near-invisible ambient shadow (0 1px 3px rgba(0,0,0,.04)); inner stage ~440px tall with the scene dead-centered; hairline divider then a 44px footer bar with two ghost buttons ("Export WAV", "Copy sound" — #f5f5f5 fill, radius 10, 13px medium).
- Category pills: 4×2 grid, pill size ≈ 135×36px, gap ≈ 10px, radius ~14px, white fill; active pill gets 1px #e8e8e8 border + soft shadow, inactive pills sit borderless on white. 9px colored dot + 15px label, left-clustered.
- Below pills: a v1/v2 segmented control (~95×33px, #ededed track, white raised knob with shadow, radius 12) flanked by two 11px gray annotation captions with ← → arrows, right-aligned on the left side and left-aligned on the right — symmetric editorial labels ("The core library… strict bounds →" / "← The remix engine… learned taste").
- "Recent sounds": 28px section heading, then a card (radius 12, 1px #ececec) of 45px rows with 1px dividers; play glyph left, mono name, right-aligned mono metadata + copy/download icons at 16px.
- "Use it in your project": numbered steps — 28px circle badge (#f2f2f2, gray numeral) — title + body + occasional ghost button; step 3 is a full-width code block (1px #e5e5e5, radius 12, mono 14px, padding ~16×20).
- Footer: hairline divider, two centered 13px gray links (dev mode, third-party notices). Fixed 36px black circular logo badge bottom-left.

## Card anatomy
The playground card is ~88% stage / 12% action bar. Stage anatomy is constant across scenes: centered prop, then a spaced-uppercase mono caption ~56px below it (11px, letterspacing ~0.2em, #b5b5b5) with scene-specific witty copy: "TAP IT TO REPLAY", "CLICK TO FAIL AGAIN", "CLICK TO WORRY AGAIN", "CLICK TO CELEBRATE AGAIN", "CLICK FOR ANOTHER PING", "HOVER TO REPLAY", "CLICK TO REPLAY". Export/Copy actions persist across all scenes in the footer bar.

## Type & color
- Grotesk sans (Helvetica Neue-like) throughout. H1 ~58px/1.05, weight 500-600, tracking ≈ -0.02em, near-black #161616. Subhead 16px #8a8a8a; tagline 14px medium #4a4a4a. Section headings ~28px/600. Body 15px #6f6f6f, line-height 1.5.
- Mono second voice everywhere data lives: sound names (tap-w5bna), metadata (1160 Hz · 0.22s, sweeps written "900→500 Hz"), stage captions, code.
- Resting palette is strictly monochrome — the only color on an idle page is the eight 9px category dots. Color arrives through the scenes: error crimson #e91337, warning amber #ee9300, success green #26bd76, notification/iOS blue #1a7ef0, tap cyan #17a8e8, hover violet #7b5bef, transition teal #14b8a6, experimental magenta #c026d3. Neutrals: #f5f5f5 fills, #ececec borders, #9a9a9a secondary, #b5b5b5 captions.
- Experimental waveform is a 3px stroke gradient pink→orange→violet (≈ #f43f8e → #f97316 → #a855f7).

## Graphic language
Every category is depicted diegetically — a fragment of real UI or a character, never an icon:
- Tap: white pill button with a hand-drawn radial dash burst (irregular 2px strokes, random lengths/angles — regenerated per tap).
- Hover: a "Hover me" button that physically lifts (translateY + layered shadow) under the cursor.
- Transition: a generated watercolor-blob image card crossfaded by an iOS toggle beneath it.
- Success: a toast card (green check circle, "Success / Everything worked") with physics confetti.
- Error: a squishy crimson blob character; Warning: a rounded amber triangle — both with minimal procedural faces (dot or slash eyes) that differ every replay.
- Notification: an iMessage-style thread — gray incoming left, blue outgoing right, blue "Again" pill button.
- Experimental: a raw oscilloscope waveform drawn across the full card width.
The characters and props are procedurally varied exactly like the audio — the graphic system embodies the product thesis.

## Motion timeline
Screen recording, one continuous take (~2.3 extracted fps; t = frame/2.30). Not a loop — a guided category tour: v1 pass → v2 remix pass → return.
- 0.0–2.6s — Tap ×3: on each click a radial dash burst fires outward and fades (~350ms ease-out, dashes staggered 0–60ms, pattern re-randomized); simultaneously a new `tap-xxxxx` row prepends to Recent sounds.
- 2.6–4.8s — smooth scroll (~700ms) down past the now 9-row list to "Use it in your project", back up at 4.8s.
- 5.2–7.8s — Error: crimson blob spring-pops in (scale 0→~1.06→1, ~400ms, single overshoot), squishes on each replay; blob silhouette and face regenerate per click (dot eyes → slash eyes).
- 7.8–9.6s — Warning: amber triangle pops with the same spring; wobble on replay.
- 9.6–13.5s — Transition: toggle off → image fades out (~300ms); toggle on → a NEW generated image fades in; knob slides ~200ms ease-in-out; repeated.
- 13.5–16.5s — brief Hover visit, then Success selected.
- 16.5–22.6s — Success ×3: toast pops (spring ~350ms) as confetti bursts upward then falls with gravity + drag, settling ~1.2s; confetti layout differs each time.
- 23–31.3s — Notification: each blue "Again" click spawns a reply bubble pair; bubbles spring in (~300ms, slight overshoot), the stack translates up ~250ms ease-out, older bubbles fade to ~50% opacity — a working chat, not a mock.
- 31.7–35.6s — Experimental: gradient waveform draws left→right (~600ms ease-out), new curve every replay; the v1/v2 control and its captions gray out (true disabled state) and the caption swaps to "Category-agnostic… In testing. Press at your own risk."
- 35.6–43s — clicks v2: knob slides right, pills re-enable; Notification and Transition replayed under the remix engine (new bubbles, new image).
- 43–50.8s — Hover: repeated hovers; button lifts ~2px with shadow growth ~150ms ease-out and settles back.
- 51.3–55.2s — Success v2 confetti, then v1 reselected.
- 55.6–60.8s — returns to Tap, two final bursts, ends idle on the hero.

## Why saved
No owner note. This is the owner's north star executed in audio: "motion that SHOWS the feature instead of describing it," on an airy premium light page. The craft moves a generic AI page would never make: (1) each sound category demos itself inside the UI fragment where that sound actually lives — you hear tap on a tap, hover on a hover, notification inside a chat; (2) the visuals are procedural like the product — blob faces, confetti scatter, waveforms, and generated images differ on every replay, so the page *demonstrates* "never the same kit twice" rather than claiming it; (3) the marketing page is the product — every play writes a real row with real Hz/duration metadata (including sweep notation "900→500 Hz") into a live list; (4) state honesty — Experimental disables the v1/v2 toggle and rewrites its caption; (5) editorial micro-copy in spaced mono per scene ("CLICK TO WORRY AGAIN"); (6) color discipline — a fully monochrome resting page where color only ever enters through the demos.

## Extractable rules
- Demo each feature inside the UI fragment it serves: put the tap sound on a tappable button, the notification sound in a chat thread.
- Keep the resting page monochrome; let accent color arrive only through interactive scenes (here: eight 9px category dots as the sole idle color).
- Regenerate demo visuals on every replay (blob face, confetti scatter, waveform) so the demo proves a "generative" claim instead of stating it.
- Make the demo write real data: prepend a row with name + Hz + duration to a live list on every interaction.
- Give every scene a spaced-uppercase mono caption (11px, 0.2em tracking, #b5b5b5) with scene-specific playful copy.
- Spring pop-in for characters: scale 0→1.06→1, ~400ms, one overshoot; re-squish on replay.
- Confetti: impulse burst then gravity+drag fall, 1.0–1.4s settle, re-randomized per fire.
- Chat choreography: new bubble springs in ~300ms, stack shifts up 250ms ease-out, older bubbles fade to ~50%.
- Hover feedback: translateY(-2px) + shadow growth in ~150ms ease-out.
- Disable dependent controls for incompatible modes and swap their explainer caption — keep real states in marketing demos.
- Annotate a central control symmetrically: left caption right-aligned with "→", right caption left-aligned with "←", 11px gray.
- Use a mono voice for all data (names, Hz, durations, code) against a grotesk display voice; write ranges as "900→500 Hz".
- Card system: radius 12–14px, 1px #ececec borders, shadows ≤ 0 1px 3px rgba(0,0,0,.04); ghost buttons #f5f5f5 at radius 10.
