# One GPU rendering vocabulary across live canvas, stills and video

## Evidence and access

The supplied X URLs were attempted directly and returned HTTP 403 to the web fetcher. Public metadata and original media were retrieved separately, with per-asset hashes. All supplied images and the full video overviews were visually inspected. Videos use 16 overview samples plus continuous 4fps low-resolution change analysis; selected one-second windows use 8fps native-resolution frames. This is sampled visual analysis, not a claim that every decoded frame was manually watched. Source dimensions are not CSS measurements.

- Video `video_1.mp4`: 998x720; 50.433s; nominal rate 60/1; 16 overview samples.
- Portable evidence: [media](../media/vercel-2092999180780556643/). Full-resolution video and denser local samples stay outside the portable package.

## What is visible

A montage presents a prismatic hero, luminous edge graphics, dark wave fields, a sunset ocean, an interactive digit example, transmissive geometry and a star-like field. Later frames show headless/export workflow and a pixelated ocean render. The linked vgpu site separates live, image, video and test presentations of related shader content.

## Composition, material and visual weight

The best-looking examples have a clear large-scale form before fine shader detail. The ocean uses a distant bright horizon, coherent wave normals and fine moving speculars. Transmissive geometry shows lighting continuity across surfaces. The surrounding demonstrations are quiet so rendering differences remain comparable.

## Timeline and interaction evidence

The 50.43s clip is a montage with multiple cuts, not one loop. Around 20s it shows monochrome surface motion, 23s a sunlit ocean, 30-34s optical objects, and the final segment shows a headless/video workflow. Cut points must not be interpreted as shader transition timings.

## Transferable construction

Define a renderer interface that can paint a deterministic time and parameter state. Reuse it for live inspection, poster capture and video export. Keep the DOM content and keyboard controls independent. Compare actual output at representative timestamps and measure the selected workload; a GPU API does not itself guarantee speed or visual quality.

## Limits and risks

The primary repository and site confirm the library's cross-runtime WebGPU purpose. The montage alone does not prove a frame-rate budget, CPU cost or identical performance across backends. The project's actual dependency and browser support should be checked before adopting it.
