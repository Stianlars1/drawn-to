# ShaderGradient — open-source animated gradient tool

## What we see
A text-only recommendation post (no photos, no video) by Aniket Pawar (@alaymanguy) pointing to https://shadergradient.co/ — "Shader Gradient: Create beautiful moving gradients on Framer, Figma and React." The pitch: a shader playground for designers/design engineers with Figma and Framer plugins, copy-paste React code output, and a fully open-source codebase (MIT, ruucm/shadergradient, ~2.1k stars). Engagement skews heavily toward saving: 899 bookmarks vs 521 likes (1.7:1) at 35k views — classic utility-resource signal.

## Layout & composition
No media attached to the post; only an X link card (OG image 800x419). The tool itself renders a full-bleed WebGL canvas (`ShaderGradientCanvas` via react-three-fiber) with a mesh deformed and colored by a fragment/vertex shader — three mesh types: `plane`, `sphere`, `waterPlane`. Output is edge-to-edge, borderless, radius-free; it is a background/surface material, not a card component. Configuration lives at shadergradient.co/customize and serializes the entire state into the URL query string (`control='query'` + `urlString`), so every preset is a shareable/deep-linkable link.

## Type & color
No typography in the reference itself. Color model of the tool: exactly three color stops (`color1`, `color2`, `color3`) blended by the shader — the three-stop constraint is what keeps results harmonious rather than muddy. Perceived brightness/contrast is controlled separately via `brightness`, `lightType` (`3d` vs `env`), and environment presets (`city`, `dawn`, `lobby`); a `grain` toggle with `grainBlending` adds film-grain dithering that kills gradient banding on large soft blends. Works for both light and dark surfaces depending on chosen stops.

## Graphic language
Real-time WebGL shader, not baked assets: vertex displacement driven by `uTime`, `uSpeed`, `uStrength`, `uDensity`, `uFrequency`, `uAmplitude` produces the organic "liquid cloth" motion; `waterPlane` is the signature ripple look. Camera is parameterized (`cAzimuthAngle`, `cPolarAngle`, `cDistance`, `cameraZoom`) plus mesh `position/rotation XYZ`, so one shader yields hero backgrounds, orbs (sphere), or horizon planes from the same primitives. `reflection` and `wireframe` flags extend the range from glossy-soft to technical. Motion character: continuous ambient loop — `loopDuration` gives a mathematically perfect loop (for video export), `animate: off` + a fixed `uTime` freezes any single frame as a static gradient. Typical ambient use runs slow (uSpeed well under 1) — the aesthetic is drift, not choreography.

## Extractable rules
- Render animated gradient backgrounds as live WebGL (`@shadergradient/react`) instead of exported video — infinite loop, ~0 asset weight, resolution-independent.
- Constrain gradient palettes to exactly 3 color stops; get variation from motion and lighting, not more colors.
- Always enable grain on large soft gradients to prevent 8-bit banding.
- Serialize visual-config state into the URL query string so every preset is a shareable deep link.
- For perfect loops, drive animation from `loopDuration` math, not open-ended time accumulation.
- Freeze a specific `uTime` with animation off to extract a static poster frame from a motion system.
- Keep ambient background motion slow (uSpeed < 1); shader backgrounds should drift, never demand attention.
- Choose `waterPlane` for hero horizons, `sphere` for orb/brand marks, `plane` for flat texture fields.
- Prefer environment-map lighting presets (city/dawn/lobby) over point lights for softer color blends.
- Distribute design tooling where designers already work: Figma plugin + Framer component + copy-paste React from one shared core package.
- Split tool architecture into a stateless renderer core and stateless UI controls so hosts (Figma/Framer/web) stay thin.
- Open-source (MIT) the renderer to make it fork-able into design systems — adoption follows ownership.
