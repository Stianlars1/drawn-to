# Landscape iOS onboarding and trackpad UI for Hilium

## What we see
A 64s screen recording (iPhone 17 Pro Max simulator, iOS 26.5, landscape) of Hilium - an app that turns an iPhone into a Mac trackpad. It walks the entire flow: 4-step onboarding (hero render, install illustration, permission coach-mark, Mac discovery), a "You're all set" confirmation, an in-app simulated macOS menu-bar tutorial, the Nearby Macs device list, Settings, passcode pairing, and the live trackpad surface with a System Control sheet. Every screen is natively composed for landscape - no stretched portrait layouts.

## Layout & composition
- Frame: simulator on a light-gray canvas (#dde1e2); app runs edge-to-edge dark (#080808) inside the landscape phone (~2868x1320 pt-equivalent).
- Onboarding uses a consistent 50/50 split: left half = visual stage (render/illustration/logo), right half = text column, left-aligned, with title → subtitle → button stack → microcopy. The Dynamic Island sits on the left edge and the visual stage absorbs it - text never collides with it.
- Right column: title ~28-30pt, subtitle ~15pt starting ~8pt below, button stack ~56pt below subtitle, footnote ~12pt centered under buttons.
- Buttons: full-column pill/capsule buttons ~44-48pt tall, radius ~22-24pt, fill #2a2a2a; stacked pairs with ~10pt gap.
- Main screens (Nearby Macs, Settings): single content column ~66% of screen width, left-aligned ~120pt from screen left; large title ~30pt bold; rows are #1d1d1d cards, radius ~16pt, ~52pt tall, ~14pt internal padding; ~24pt gap between title block and first card; no borders anywhere - separation is purely fill-on-fill (#1d1d1d on #080808).
- Sheets (Passcode, System Control) rise from the bottom as full-width rounded panels (radius ~24pt top corners), with a circular ✕ dismiss at top-right (~36pt).
- Passcode screen splits again: title + helper + 5-dot progress on the left, a 3x4 circular numpad (~52pt keys, ~14pt gaps) on the right - the numpad lands under the right thumb in landscape.
- Trackpad view: near-black canvas, top-left window-switcher chip, right-edge vertical rail (keyboard button top, tall pill with display button center, circular back chevron bottom) - all controls pushed to the right bezel where the thumb rests.

## Card anatomy
- Onboarding steps are 50/50 visual-to-text; the visual stage is always a constructed object, never a screenshot dumped in: (1) 3D top-down iPhone render with a floating "MacBook Pro" pill selector; (2) oversized macOS-style Hilium icon tilted ~15° overlapping a glass Applications folder icon with a volumetric light beam above and a hand-drawn white arrow + "Applications" label; (3) a miniature 3D-tilted phone frame showing the real iOS local-network permission dialog with a hand-drawn yellow marker ellipse around "Allow"; (4) the Hilium asterisk-arrow logo rendered as giant dark-on-dark embossed relief filling the entire left half, bleeding off-screen.
- Device row card: leading monitor glyph with status dot overlaid on its corner (yellow = known/unreachable, green online), 15pt medium label, trailing chevron.
- "Add another Mac" card: same geometry but with a barely-visible green wash (#0e150e) to whisper "action", leading ⊕ in a circle, two-line title+caption, trailing ✕ (dismissible).
- System Control sheet: connected-Mac summary card (glyph + name + green CONNECTED pill badge), then a key-value sub-card (MAC PASSCODE 40575 / IP ADDRESS masked as ******), then labeled sections: Power Controls (4 equal circular icon buttons: sleep, restart, power, lock), Bluetooth Devices (rows with device glyph, name, battery % + battery icon), App Shelf (horizontal row of real Mac app icons as launch shortcuts).

## Type & color
- SF Pro throughout; hierarchy by weight and gray value, not size jumps: titles ~28-30pt semibold #ffffff; body/subtitles ~15pt regular #8e8e93; footnotes ~12pt #6e6e73; section labels ~13pt #8e8e93.
- Palette: bg #080808, elevated card #1d1d1d, sheet #161616, button fill #2a2a2a, pressed key flash ~#7b7b7b.
- Accent discipline: color = state only. Cyan-blue (#2f8fe0-#1fb6e1) appears solely in onboarding artwork (radar rings, Applications folder); green (#41974c fill, #5bbe6b dot) means available/connected - the Continue button silently turns green with a green-dot caption "Mac is available on this network" the moment discovery succeeds; yellow (#eaed48) marks a known-but-unverified device and the coach-mark scribble. Everything else stays grayscale.
- Contrast strategy: three grays of text on two grays of surface; interactive emphasis via fill lightness, never borders or blue links (the only text links are ToS/Privacy in slightly lighter gray).

## Graphic language
- 3D product renders (top-down iPhone, metallic "You're all set" coin with a rotating specular sheen) instead of flat vectors.
- Skeuomorphic macOS iconography (glass Applications folder, realistic Hilium icon) with a volumetric god-ray glow to depict "install the Mac app".
- Hand-drawn annotation layer: white marker arrow ("Applications"), yellow marker ellipse drawn on around the real permission dialog's Allow button - human coach-marks over real UI fragments.
- Brand-as-texture: the logo used as an embossed dark relief background (visible only through highlights/shadow, ~4% lightness delta) - dark-on-dark like Linear-era editorial UI.
- Real UI fragments as illustration: an actual iOS permission sheet inside a tilted phone frame; later a fully working replica of the macOS menu bar + Hilium dropdown (passcode field, status rows, hover highlight) rendered inside the iPhone app as a tutorial.
- The trackpad surface itself is depicted as a dot-matrix grid (~14pt pitch) that lights up in ripples - the feature is shown by its own feedback, not described.

## Why saved
No owner note. The tweet text: "Most apps tend to ignore landscape mode. I wanted to make sure that wasn't the case with Hilium. And who knew designing for landscape mode would be fun?" - the save is about landscape as a first-class layout, and the craft holds up: every screen is re-composed, not rotated. The 50/50 visual/text split turns the awkward wide aspect into an asset; the passcode numpad migrates to the right thumb zone; the trackpad's controls hug the right bezel; the Dynamic Island is absorbed by the visual stage. On top of that, three moves a generic page would miss: (1) feature-shows-itself motion - Continue turns green when the Mac is discovered, the trackpad announces itself with a dot-matrix ripple wave, touch feedback is a radial dot ripple; (2) real-UI-as-illustration - an actual permission dialog in a tilted mini phone with a hand-drawn marker ellipse, and a working replica of the macOS menu-bar dropdown embedded in the iOS tutorial; (3) borderless dark editorial surface system - #080808/#1d1d1d fills, embossed logo-as-texture, color reserved exclusively for state. This is exactly the owner's profile: motion that demonstrates instead of describing, on an editorial dark UI.

## Extractable rules
- In landscape, split onboarding 50/50: visual stage left, left-aligned text column right; never center a portrait layout.
- Let the visual stage absorb the notch/Dynamic Island side; keep text on the clean side.
- Build dark UI with fills only: bg #080808, cards #1d1d1d, buttons #2a2a2a, radius 16-24pt, zero borders.
- Reserve color for state: green #41974c = connected/available, yellow = known/unverified, blue only inside artwork.
- Confirm async success passively: morph the primary button to green and fade in a green-dot status caption, no modal.
- Annotate real UI screenshots with hand-drawn marker strokes (arrow, ellipse) and draw them on in ~600ms.
- Tilt embedded screenshots ~10-15° inside a 3D device frame; never paste them flat.
- Use the brand mark as dark-on-dark embossed relief (~4% lightness delta), oversized and bleeding off-canvas.
- Teach a companion-app flow with a working in-app replica of the other platform's UI, not a static picture.
- Place primary touch targets (numpad, control rail) in the landscape right-thumb zone.
- Visualize an invisible surface (trackpad) as a dot grid that ripples on activation (~800ms travelling wave) and on touch (~600ms radial decay), then fades to black.
- Keep screen pushes at ~400-450ms ease-out with iOS parallax (old screen slides ~40% and dims).
- Echo iOS passcode conventions but adapt them: horizontal dot progress, last digit shown as numeral for ~250ms before collapsing to a dot.
