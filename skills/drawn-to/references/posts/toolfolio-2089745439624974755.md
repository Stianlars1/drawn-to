# Rare UI animated React component playground tour

## What we see
A 41s continuous screen-capture tour of rareui.com - "the free component encyclopedia," a shadcn-registry library of niche animated React components by swamimalode07 (posted by Toolfolio, Day 298). A dark two-panel playground app floats over a grainy orange/magenta mesh-gradient wallpaper; the cursor walks an 11-item sidebar and live-demos each component: frosted-glass folder, bounce sidebar, morphing duration picker, fluid orb, scroll-progress pill, themable code block, gravity letters, OTP input, GitHub heatmap, emoji toss. The tour ends by opening a right-hand description panel with real props tables and npm/pnpm/yarn/bun install commands.

## Layout & composition
- Stage: app window (radius ~16px, 1px border rgba(255,255,255,0.06)) centered on a full-bleed mesh gradient (orange #F97316 → red #DC2626 → magenta/indigo edges) with heavy film grain; window occupies ~82% width, ~85% height.
- Two detached rounded panels with a ~6px gutter: sidebar ~165px wide (at 1280 scale ~210px) and content canvas, both radius ~12px, fill #121212 on canvas, #151515 sidebar.
- Sidebar: "Components" eyebrow ~11px #777, 11 items at ~12px, 24px row height, left padding ~20px; active item = white text + 4px orange dot bullet.
- Canvas toolbar: 3 icon buttons top-right (~24px, radius 6px, icon 14px): center/fit, code toggle ("Open description"), theme toggle; tooltips are 11px dark chips, radius 6.
- Floating variant dock bottom-center of canvas: dark pill #1C1C1C radius ~10px, 6-dot drag handle at left, 14px circular color swatches, ~6px gaps.
- Description panel: slides in as a third column (~35% width), sections divided by hairline rules; props rendered as mono chips (prop name in bordered tag, type in muted mono) + description column.
- Component demos centered in canvas with generous negative space (component occupies <20% of canvas area).

## Card anatomy
Not a card grid - a single-stage playground. Per-demo anatomy: component centered, one hint line of muted 11px text below it ("Enter 123456 to pass. Any other code fails."), variant dock at bottom. Ratio is roughly 80% empty stage / 15% component / 5% chrome.

## Type & color
- UI chrome: system-ish grotesque, 11–12px, muted #8A8A8A on #121212, white #F5F5F5 for active.
- Docs pages (bounce-sidebar and scroll-progress demos) use a rounded geometric sans (Poppins/Bricolage-like): page title ~30px/600 with hairline underline rule, section heads ~16px/600, sub-labels 11px #6E6E6E uppercase-ish eyebrows, body ~12.5px/1.6 #9A9A9A.
- Accent: single orange-red ~#FF4D00 (active nav dots, OTP active digit, code keywords, syntax theme).
- Semantic states: success green ~#22C55E (OTP outlines, GitHub heatmap ramp), folder blue ~#4D9FEC.
- Contrast strategy: near-black canvas + mid-gray text keeps demos the brightest thing on screen; the saturated wallpaper supplies all color while the app itself stays monochrome + one accent.
- Light mode exists and is shown (~#ECECEC canvas): all components re-theme via tokens, demonstrated live.

## Graphic language
No illustration in the traditional sense - the components ARE the graphics: a frosted-glass folder (blurred translucent flap over detailed white "paper" sheets with text-line marks, dark-paper variant in light folder), a soft-gradient fluid orb with a swirling internal blob, an LED-like green contribution heatmap, native-emoji physics particles, glyphs as physics bodies. Realism cues: glassmorphism blur on the folder flap, paper sheets fanned at distinct angles, dashed-border drop zones, mono chips for props. The wallpaper's grain + mesh gradient gives editorial texture behind an otherwise flat UI.

## Motion timeline
t = frame/3.39 fps (140 frames / 41.28s). Two motion layers: in-app component animation + camera choreography (zooms/pans with motion blur, ease-out expo, ~500–700ms).

- 0.0–1.8s - Cold open, macro shot: frosted folder on black. Hover opens it: flap rotates forward ~25°, three papers rise ~40px with ~60ms stagger and slight fan rotation; spring, mild overshoot, ~500ms.
- 1.8–3.0s - Camera zooms out (~700ms, expo-out) revealing the whole playground; variant dock appears; folder switches white → blue via dock swatch (recolor crossfade ~300ms).
- 3.5–4.1s - Second hover open/close of blue folder; same spring.
- 4.1–5.6s - Theme toggle: full app flips dark → light (~250ms fade), "Toggle theme" tooltip shown, then back to dark.
- 5.9–8.6s - Bounce sidebar: wiki-style "Rare UI" doc page; clicking CONTENTS items (Introduction → History → Overview → Architecture → References) scroll-jumps content; the orange active-dot slides between items with spring overshoot (the "bounce", ~400ms); camera holds a 3D-tilted perspective during close-ups, then levels out.
- 8.9–14.2s - Duration Picker: compact pill "0 Hr. 0 Min. ✏️". Click pencil → pill splits and morphs into two input segments + check button (shared-layout width expansion, spring ~350ms). - 14.8–17.7s - Fluid Orb: sphere with continuously swirling gradient blob (slow ~4s loop); dock swatches crossfade hue red → orange → green (~400ms each).

## Why saved
No owner note. This is squarely the owner's taste: motion sequences that SHOW the feature instead of describing it, executed at design-engineer grade. The verifiable craft: (1) every component is demonstrated through real interaction, not autoplay - cursor hovers, typing, and clicks drive everything; (2) the demos carry state logic a generic AI page would skip - the OTP has an actual pass/fail rule printed under it, the duration picker does a true shared-layout morph in both directions, the scroll pill maps one scalar to both ring fill and section label; (3) the doc pages contain genuinely written rationale copy ("Two to four pixels is enough to register in peripheral vision"), not lorem - even though other demo pages deliberately use lorem as placeholder texture; (4) restraint in the shell - monochrome dark chrome with a single orange accent lets the saturated wallpaper and the components own all color; (5) the video itself is choreographed like a product film: one continuous take, expo-out camera zooms with motion blur, ~3s per component, macro close-ups for detail beats. It is simultaneously a component library reference and a template for how to film one.

## Extractable rules
- Float the app window (radius 16px, 1px rgba(255,255,255,0.06) border) over a grainy mesh-gradient wallpaper; keep the app monochrome so the wallpaper owns the color.
- Split sidebar and canvas into detached rounded panels (radius 12px, ~6px gutter) instead of one continuous surface.
- Mark active nav with a 4px accent dot + white text, and animate the dot between items with a ~400ms spring overshoot.
- Demo components via recorded cursor interaction (hover, typing, clicking), never autoplay loops.
- Give every interactive demo a one-line muted hint (11px, #8A8A8A) stating the rule of the demo ("Enter 123456 to pass").
- Put variant/color controls in a floating bottom-center dock: dark pill, drag-handle dots, 14px swatches.
- Morph compact display pill ↔ expanded edit inputs with shared-layout width animation (~350ms spring), confirm collapses back.
- Signal OTP success by flashing all cell outlines green simultaneously (~200ms), highlight the active digit in the accent color.
- Track scroll with one scalar mapped to both a circular ring fill and a live section label in a floating pill.
- Keep one accent (#FF4D00-range) for all active states, code keywords, and markers; reserve green strictly for success/data.
- Prove theming by toggling dark/light live mid-demo; components must re-skin via tokens with a ~250ms fade.
- Film feature tours as one continuous take: expo-out zooms (~600ms) with motion blur between beats, ~3s per feature, macro close-up for the detail moment.
