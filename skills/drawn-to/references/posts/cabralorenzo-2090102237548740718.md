# Draggable tick-wheel humidity dial

## What we see
A single "Humidity" card on a warm off-white dot-grid canvas containing a circular tick-burst dial. The user grabs the ring with a hand cursor and spins it like a physical wheel: the big center numeral tracks the pointer 1:1 (62 → 92 → 8 → 47 → 99 → 3), the filled tick arc grows/shrinks, and the whole system recolors by zone — green NORMAL, blue HIGH, orange CRITICAL — with a status pill and a fixed setpoint marker at 60%. Tweet text: "component wheel. testing interactions".

## Layout & composition
- Canvas: warm off-white #F2F1EE, dot grid of ~2px dots at ~32px pitch, #D8D6D1.
- Single card ~460×458px, centered; bg #FBFAF8; radius ~24px; shadow ~0 2px 10px rgba(0,0,0,0.05); no visible border (possibly 1px rgba(0,0,0,0.03)).
- Card padding ~24px. Header row: title left, status pill right; dial centered below; caption bottom-center.
- Dial: ~290px outer diameter, ring of ~60–64 radial ticks (~4.5° pitch), sweep ≈ 290° with a ~70° gap centered at 6 o'clock; arc starts bottom-left (~7:30) and runs clockwise to bottom-right (~4:30).
- Ticks: stroke ~2.5–3px; inactive length ~22px; active ~30px baseline, up to ~45px when magnified; inner radius ~65px around the numeral.
- Fixed setpoint marker: a lone ~12px gray slash floating just outside the ring at the 60% angle (~1:30 position); never moves.
- Status pill: ~100×36px, full-radius, bg #EDECE9, 7px colored dot + uppercase label, 12px gap from card edge.
- A small gray dash above the card top-left is a canvas/recording artifact (Framer-style component label), not part of the component.

## Card anatomy
Visual (dial) is ~70% of card height; text is one title line, one pill, one caption. Title "Humidity" top-left; live value lives inside the dial center (numeral + small % suffix); "Setpoint 60%" caption bottom-center in muted mono. No description text at all — the state pill and colors do the explaining.

## Type & color
- Title: geometric sans (Inter/Helvetica-class), ~22px, weight 500, #1F1F1D.
- Center numeral: ~52px monospace (same family as caption; mono with curved 7, flat-top 4), #1A1A1A, with a ~20px gray "%" suffix (#9A9891) offset right and below the cap line.
- Pill label + caption: uppercase/regular monospace ~13–15px, letter-spacing ~0.06em; pill text #3A3A38, caption #B4B2AB.
- Zone palette — NORMAL green ≈ #35A25B, HIGH blue ≈ #3E63F2, CRITICAL orange ≈ #C9661C; inactive ticks #D9D7D2. Active run fades toward the arc start (tail opacity ~0.45), full saturation at the leading edge.
- Contrast strategy: near-monochrome warm neutrals everywhere; the single zone hue carries all state meaning across ticks, pill dot, and nothing else — text stays ink-dark.

## Graphic language
Pure UI-fragment vector work: the gauge is drawn as discrete stroke ticks rather than a continuous arc, which lets each tick animate length independently (dock-style magnification) and makes the fill boundary read as a physical pointer position. Cursor is the system grab/grabbing hand — the component advertises wheel physics via cursor alone. The dot-grid backdrop and mono captions give it an instrument/industrial-panel tone without any illustration.

## Motion timeline
Source: 10.78s, 1042×1004, ~53.4fps effective (576 frames). t = frame/53.4.
- 0.0–0.55s: idle at 62% NORMAL. Active green run already shows its length ramp peaking at the leading-edge tick.
- 0.55–1.5s: open-hand cursor enters right, hovers the ring; ticks within ~40° of the pointer magnify (~1.3–1.6×), spring-smoothed ~150–250ms — a macOS-dock fisheye on the ring, applied to active and inactive ticks alike.
- 1.5–2.3s: mousedown (cursor → grabbing fist), clockwise drag along the circumference: 62 → 85 → 93. Numeral updates every frame with zero smoothing lag (true direct manipulation, no tween on the value). Crossing ~75–80 flips NORMAL→HIGH: all active ticks recolor green→blue and the pill swaps label+dot in a fast crossfade (~120ms), no layout shift.
- 2.3–3.9s: reverses counter-clockwise through 64 (green again) and keeps sweeping down; below ~30 the state flips to CRITICAL — only a handful of orange ticks remain near the arc start (25 → 8 → 4). Releases at ~3.85s; value stays where dropped, no snap-back.
- 4.4–5.4s: re-grabs bottom-left, drags up 4 → 21 → 31 (NORMAL returns at ≥30) → 44, releases at 47.
- 6.5–8.2s: grabs the leading edge, spins up 47 → 70 → 86 → 91 → 95 → 99 (clamps at 99), HIGH blue.
- 8.2–10.4s: winds back down 99 → 90 → 44 → 3, ending CRITICAL.
- 10.4–10.78s: releases, hand cursor exits below the card. Loop is not seamless (starts 62, ends 3).
Easing character: value = linear/1:1 with pointer; tick length = small spring (slight overshoot visible on magnify/demagnify); state color/pill = discrete swap with quick crossfade; tail opacity gradient is static.

## Why saved
Owner note: "showcase of an interactive 'wheel' component. Liked: controlling a slider via a spinning wheel — simple but powerful."
Verified — and the note undersells the craft. The wheel idea works because of four decisions a generic build would miss: (1) the gauge is built from discrete ticks, not an arc, so the pointer-proximity fisheye can exist — ticks under your hand physically reach toward the cursor, which is what makes it feel like touching a wheel; (2) the numeral is never tweened — it tracks the pointer per-frame, so the control feels like a hardware encoder rather than an animation; (3) state is encoded three times in one hue (tick color, opacity-ramped arc, pill dot) while everything else stays warm gray, so zone changes land instantly without noise; (4) small instrument-panel details — the fixed setpoint slash at the 60% angle, the mono numerals, grab/grabbing cursors, active-tick length ramp fading toward the tail — give it a physicality that survives even in still frames.

## Extractable rules
- Build circular gauges from ~60 discrete stroke ticks (~2.5px, ~4.5° pitch) so each tick can animate independently.
- Sweep ≈ 290° with the gap centered at 6 o'clock; start the fill at bottom-left, run clockwise.
- Magnify ticks within ~40° of the pointer to ~1.5× length with a ~200ms spring; apply to inactive ticks too.
- Make active ticks ~35% longer than inactive ones, and ramp both length and opacity up from arc-start to the leading edge (tail at ~0.45 opacity).
- Never tween a direct-manipulation value: update the numeral 1:1 per pointer event; save easing for secondary elements only.
- Encode state zones (thresholds here: <30 critical, 30–75 normal, >75 high) by recoloring the entire active run plus a status-pill dot; keep all text ink-neutral.
- Swap state colors and pill labels discretely with a ~120ms crossfade — no sliding or scaling on threshold cross.
- Mark reference values (setpoint) as a fixed slash outside the ring at the correct angle; label it in muted mono below the card.
- Use cursor: grab / grabbing as the only affordance for wheel controls — no visible handle needed.
- Pair a geometric sans title with monospace numerals and captions for instrument-panel tone; letter-space uppercase labels ~0.06em.
- Clamp the range visibly (caps at 99) and let released values stay put — no snap-back.
- Set the scene on a warm off-white (#F2F1EE) dot grid (~32px pitch) with a near-white card, ~24px radius, shadow under 6% opacity.
